# MaiBot Minecraft 2.0.0：Java 26.2 原生后端

## 这次不是换版本号

新版以 Java **26.2 正式版 / 协议 776** 为目标，直接连接真实服务器，不需要 ViaProxy、ViaBackwards 或 Node。
Python 插件包含独立的登录/configuration/play 编解码器、26.2 区块格式和官方注册表数据。
保留旧 1.20.1 / 763 后端用于回归；26.1、26.3、基岩版、自定义模组协议不在支持范围。

## 只有地址、没有端口

服务器通常就是默认端口 **25565**，面板不显示端口很常见。本版按原版客户端规则处理：

| 你填的 | 插件怎么连 |
| --- | --- |
| `mc.example.com` + 端口 0/留空 | 先查 `_minecraft._tcp.mc.example.com` 的 SRV 记录，查到就按记录连；查不到用 25565 |
| `mc.example.com:25570` | 直接用 25570，不再查 SRV（与原版一致） |
| `1.2.3.4`（IP） | 不查 SRV，用 25565 |
| `[::1]:25565` | IPv6 地址，端口 25565 |

所以**只填地址、端口填 0 就行**。连接日志会出现以下之一：

```text
SRV 记录：mc.example.com → connect.example.com:25570（优先级 10，权重 10）
没有 SRV 记录，使用默认端口 25565
```

`/mc diag` 里的「目标」会显示 `域名:自动端口`，连上后还会显示实际连接目标（`connect_target`）和是否用了 SRV。

注意两点：

- 握手包里发送的始终是你填写的域名，不是 SRV 目标，因此 BungeeCord/Velocity 的虚拟主机路由不会错乱。
- 如果连不上又没有 SRV 记录，说明服务器真的不在 25565，请到服务器面板/服主那里确认真实端口后写成 `域名:端口`。

SRV 查询只用标准库：DNS 服务器地址取自 Windows 注册表或 `/etc/resolv.conf`，读不到就跳过并退回 25565，不会因此连不上普通的 25565 服务器。

## Windows 升级

1. 停止 MaiBot。备份原插件目录及插件配置。
2. 用本包的整个 `maibot-minecraft` 目录替换旧插件。不要将新旧目录同时放在 plugins 内，避免同 ID 重复加载。
3. 保留你在 MaiBot 插件页里的管理员、验证码流等配置。启动后确认插件版本 **2.0.0**。
4. 在插件服务器配置中填真实服务器地址和端口，选择 **minecraft_version = 26.2**。
   如果旧配置是 `127.0.0.1:25568`，那通常是 ViaProxy；请改为真正的 26.2 服务器地址。
5. 先关闭自动连接，保存配置，手动发 `/mc connect`，随后 `/mc diag`。

```toml
[server]
host = "你的服务器地址"
port = 0                     # 0 = 自动：有 SRV 就跟随，否则 25565
minecraft_version = "26.2"
username = "MaiBot"
auth = "offline"             # 仅用于服务器本身允许的离线认证
view_distance = 8
auto_connect = false

[behavior]
autonomous = true
humanize = true
auto_eat = true
```

正版服务器配置 `auth = "microsoft"`，按设备码流程登录拥有游戏的账号；推荐在 MaiBot 的 Python 环境安装 cryptography 加速。
不要为机器人关闭公共服务器的正版验证。需要签名聊天的服务器可能拒绝本插件的未签名消息。

`auto` 模式读取状态协议：763 选旧版，776 选新版；状态查询不可用时优先 776。
显式选择 `26.2` 可避开代理伪报状态造成的误选。

## 确认能动，而不只是在线

1. `/mc diag`：应显示原生后端 **26.2 / 776**、`connected=True`。
2. 等待玩家初始坐标及区块：已加载区块应大于 0，解析失败不应持续增长。
3. `/mc goto x y z`：选择附近安全、已加载的地面坐标，观察是否移动。
4. `/mc resume` 恢复自治；`/mc stop` 仅暂停动作，`/mc disconnect` 才退出服务器。
5. 工具、方块和食物需在快捷栏；本版没有完整的工作台、箱子、合成、交易或自动整理背包。

验证码沿用原功能：标题/副标题/动作栏/聊天文本转发至配置的 MaiBot 聊天流。
`verify_stream_id` 是 MaiBot 的聊天流 ID，不是直接填写 QQ 群号；需正确配置权限与目标流。
地图图片、材质或图形验证码不在文本提取范围。

## 实际验证范围（请务必看）

已完成本地测试，包括：

- 旧版协议、物理、寻路、插件指令与验证码回归。
- 26.2 登录 UUID、登录确认、配置协商、空 known packs、keepalive 和结束配置。
- 新传送、LPVec3、use_item 和 attack 的官方 Java StreamCodec 样本验证。
- 区块样本由官方 `LevelChunkSection.write` 直接生成，覆盖 5-bit palette、不跨 long、单值 biome、空气及含水台阶；验证所有 8192 个状态。
- 本地真实 TCP 测试：776 握手→登录→配置→区块→标题验证码→传送确认→移动发包。
- 地址解析与 SRV：本地 UDP DNS 服务器双向验证查询/解析格式，并用真实域名
  `2b2t.org` → `connect.2b2t.org:25565` 验证线上解析；握手包仍发送原始域名。
- 所有内嵌包 ID 与官方 Packet Report 逐项比对一致。
- 2.0.2 起新增生存行为回归（本地 `SimpleWorld` + 模拟客户端）：水里"只跳一下 vs 一直按跳跃"
  的高度差、`swim_to_land` 真的能游到干岸、4 格厚树叶包住的树干能扒开通道后从下往上砍完、
  大脑在落水时优先自救；另有伐木几何 14 项单测。

**没有在你的服务器上实测，也没有以官方服务器完整生存游玩作为验收。** 本地 TCP 服务器是测试替身，不是官方游戏服务器。
因此这是可安装、带验证的原生实现，但不能保证所有反作弊、认证插件、自定义物品或服务器行为都兼容。
若还有问题，请提供 `/mc diag` 和对应插件日志，而不是继续更换 ViaProxy。

## 已知限制

- 物品组件仅实现部分常见编码。遇到未知附加组件，会拒绝整份背包包并记录错误，避免错位解码；可能导致工具/食物不可识别。
  `/mc diag` 会显示背包解析错误，不应误当作空背包。
- 不发送签名聊天，不验证入站玩家聊天签名；入站聊天读取原始正文，不完整应用装饰/过滤。
- 不自动接受服务器行为准则；不跟随 transfer 到另一服务器；不下载资源包。强制资源包或准则可阻止进服。
- 对话框、自定义交互、完整容器点击与合成未实现。
  **2.0.4 更新**：已实现容器点击与 2x2/3x3 合成（木板、木棍、合成台、火把、木/石工具、
  熔炉、箱子），见 [合成与光照](CRAFTING_AND_LIGHT.md)；箱子/熔炉等 GUI 的**使用**仍未做。
- 碰撞形状来自官方状态在 EmptyBlockGetter/空实体上下文的查询；不等于所有动态世界相关碰撞。
  物理是近似实现，严格反作弊可能回弹。
- 掉落表留空，不编造动态战利品结果；采集计时使用默认状态属性及官方工具标签，并非完整生存机制复刻。
- 游泳是近似实现：会持续上浮并朝最近干岸游，但不会像真人那样在水下挖通道、换气或利用水流。
  特别高的树（原木超出交互距离）只会砍掉够得着的那几截。
- 自主行为是规则驱动的"有目标"计划（木头 → 石头 → 探索 → 夜里回家），不是完整生存 AI：
  还不会合成工具、盖房子、开箱子、钓鱼或种田。
- 2.0.3 起游戏机制（挖掘时间、摔落、溺水、攻击冷却、生物行为）按 Minecraft Wiki
  Java 版规则实现，规则清单与没采用的部分见 [WIKI_KNOWLEDGE.md](WIKI_KNOWLEDGE.md)。
  其中蜘蛛"白天中立"用时间+高度近似（插件没有解析区块光照数据）。
- 尚未完整处理所有 26.2 play 包。未知包不直接套用旧版解码。
